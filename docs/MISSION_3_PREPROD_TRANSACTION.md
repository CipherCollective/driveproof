# Mission 3 · Real Preprod transaction harness

Status: the Phase 1 path was confirmed against Midnight Preprod at the `preprod-e2e-success` checkpoint documented in [`PREPROD_EVIDENCE.md`](PREPROD_EVIDENCE.md). This page remains an isolated DEV-only engineering surface. The normal Driver flow still uses its explicit mock client, and no `MidnightDriveProofClient` or fake transaction path has been added.

## What is wired

```text
Lace ConnectedAPI
  -> createMidnightRuntime
  -> FetchZkConfigProvider + local proof server 8.1.0
  -> deployContract (real constructor transaction)
  -> findDeployedContract
  -> generated proveCompliance()
  -> Lace balance/submit APIs
  -> Preprod indexer state
```

The generated contract remains in `contract/**` and is not regenerated by this harness. The generated private state is imported from `driveproof-contract`:

```ts
{
  speed: bigint,
  attestationSignature: {
    announcement: { x: bigint, y: bigint },
    response: bigint,
  },
  attestorId: bigint,
}
```

The Driver copies the existing generated files at dev/build time into the ignored public path:

```text
/contract/compiled/driveproof/keys/proveCompliance.prover
/contract/compiled/driveproof/keys/proveCompliance.verifier
/contract/compiled/driveproof/zkir/proveCompliance.bzkir
```

This follows the current official browser-dapp pattern: `FetchZkConfigProvider` reads generated assets from the application origin, while the browser wallet adapter maps `balanceUnsealedTransaction` and `submitTransaction` to the Midnight.js wallet and midnight providers.

## Local preparation

1. Confirm the existing proof server responds with `8.1.0`:

   ```powershell
   curl.exe http://localhost:6300/version
   ```

2. Start the attestor from its workspace. Its gitignored service `.env`, if needed, belongs at `attestation/attestor-simulator/.env`; it is never copied into the Driver or any Vite env file. Start it without printing the file:

   ```powershell
   Set-Location attestation/attestor-simulator
   npm run dev
   ```

   The process must already own its persistent `PROVIDER_SECRET_KEY`. Do not create a new key for this test.

3. From the repository root, start the Driver:

   ```powershell
   npm run dev:driver
   ```

## Manual browser acceptance

Use Chrome or Brave with the Lace browser extension installed and the wallet already configured for Midnight Preprod.

Open:

```text
http://localhost:5173/wallet-debug/transaction
```

Then use the isolated page in this order:

1. Select **CONNECT LACE**. When Lace opens, review the origin and select the extension's connection/authorization action. The exact confirmation label is controlled by the installed Lace version and is not assumed by this repository.
2. Select **REQUEST SAFE · EXPECT 67**. The page calls `POST http://localhost:4000/attest` with `{ "tripId": "safe" }`; the browser never sends a speed.
3. Select **BUILD PROVIDERS**. The page must show the Preprod runtime/proof-server gate passing.
4. Select **DEPLOY TO PREPROD**. Lace will require a real wallet confirmation. Approve only the transaction whose constructor values shown on the page are `speedLimit=80`, `attestorId=1`, and the supplied registered public key. Do not approve a transaction with different values.
5. After deployment finalizes, the page displays the returned contract address, transaction ID, status, block height, and block hash. Select **PROVE SAFE 67**.
6. If Lace requests a second confirmation, review it and approve the real call transaction. Success is shown only when the returned transaction has a successful ledger status and the indexed `complianceCount` reads `1`.

The page never turns a missing approval, proof error, or failed call into a transaction ID. It also never displays the private signature, private-state password, wallet seed, mnemonic, or provider secret.

## Real values used by the harness

| Input | Value |
| --- | --- |
| Network | `preprod` |
| Proof server | `http://localhost:6300` (`8.1.0`) |
| Attestor service | `http://localhost:4000` |
| Contract speed limit | `80` |
| Constructor attestor ID | `1` |
| Constructor attestor public key | The exact x/y values in `PreprodTransactionDebugPage.tsx` |
| Generated circuit | `proveCompliance` |
| Private-state ID | `driveproofPrivateState` |

The confirmed contract address, transaction IDs, block heights, and ledger result are recorded in [`PREPROD_EVIDENCE.md`](PREPROD_EVIDENCE.md), rather than duplicated in this implementation handoff.

## Failure boundaries after safe success

The page exposes two real-path checks only after `complianceCount=1`:

- attestor-issued unsafe `112` should fail at proof/circuit evaluation with the contract's rejection;
- attestor-issued `112` with local private speed replaced by `71` should fail signature verification.

Neither case is submitted as a successful transaction, and no rejection is converted into a fabricated result.

## Security boundary

The attestor process owns the persistent `PROVIDER_SECRET_KEY`. The browser receives only the attestor response and public provider metadata. The browser private-state provider encrypts the generated state with an in-memory session password; that password is not a Vite variable or a log value. The page is not a production wallet UX and is not yet the product's `DriveProofClient`.
